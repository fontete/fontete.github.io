One bad record never blocks a sync

Upserts use ON CONFLICT DO UPDATE, so a re-run is safe. Failed records are retried and skipped, not allowed to fail the batch.

Jobs survive a pod restart

E-sign monitoring state lives in the database, and cron jobs rebuild it on boot instead of relying on memory.

Errors are classified, not just logged

Transient errors are retried with backoff. Permanent errors are recorded with a reason the support team can act on.

// how I work

Plan first. Use AI to go faster. Done means verified in production.

I adopted AI coding tools as soon as they were good enough for production work, and they now shorten every stage of my workflow: Claude Code and Cursor for day-to-day building, and local LLMs when client code must stay on-premise. The tools write code faster; they don't decide what to build or tell me when they're wrong.

Spec before code

Data model, service boundaries, failure cases and acceptance criteria come first. AI helps me draft and challenge the spec, not skip it.

Build in small steps

Claude Code or Cursor scaffolds each task. I read every change line by line, looking for invented fields and missing tenant checks.

Tests that can fail

AI drafts the cases; I make sure each one would fail if the behaviour were wrong. The merge request lists what I checked.

Verify in production

Deploy, then use AI to triage logs and traces faster. Confirm it works for real users and write up what broke.
